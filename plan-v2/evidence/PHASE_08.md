The admin operations page reads local tasks, works, accepted contributions, split acceptances, music generation, model mode and bounded model draft output, and reads policy and agent earnings from the contract. It provides project creation and a bounded NEAR AI collaboration action; this action uses up to six model calls per agent with 900 output tokens and no paid music generation. The worker was changed to use the derived studio database, started successfully, rejected an unauthenticated request and created an authenticated creative session without running the model. A distinct reviewer testnet account was registered in transaction `668PCYa7C3Y4oPbXHy8arzLZ6noq7A4UwKP19NdUjCgs` and mapped in the derived catalogue database. The Phase 03 source snapshot was unchanged.

The creative form now keeps the complete request, including its deadline, in browser session storage. A reload or timeout can resume the same durable worker session. The worker accepts replay of an already-created session after its original deadline, and a test confirms no second model call. Agent model operation keys include the song brief and agent ID, so distinct briefs within a project receive independent budgets while retries reuse the same model output. `npm run verify:studio` passed after this change, including the compiled contract sandbox and built-web HTTP test. No live NEAR AI call or ElevenLabs music call was made for this check.

A new administrator song action sends a completed brief to the private worker. It requires live lyric, composition, reviewer acceptance and agreed split outputs; the worker then requests one bounded 20-second ElevenLabs recording and creates a private review version with source hashes and two contribution records. The existing music operation log prevents a second paid request on retry or an unknown outcome. A mock-provider test proves one call and one version; browser authorization and a live new-song run still need verification. The action does not bypass media review, rights or chain publication.

An administrator album action now assembles two reviewed or accepted songs from one project into a version-bound private album draft. It stores an escaped original SVG cover, a metadata blob, equal track weights and contributor shares derived from the two song splits. A persistence test verifies current song versions, deterministic shares, idempotency and changed-title rejection. New album browser use and final publication remain unverified.

The browser can now serve private draft audio to the authenticated administrator, record a human listening/rights confirmation, and change only the work state to accepted while keeping content hashes fixed. An accepted work can be quoted as an exact `create_release` payload, committed in the admin wallet and handed to the worker for agent split signatures. The worker verifies restricted on-chain access keys, checks final acceptance views, and automatically publishes with a producer key when the chain policy is autonomous. In human-review mode it waits for an admin approval. The policy confirmation route verifies a final `set_policy` transaction before updating the local music budget mode. All new mutation routes require the admin session; the built-web HTTP test rejects anonymous requests. This browser path has not yet been personally exercised by the owner.

The private worker started with the actual local configuration and reconciled the already-published `song-phase03-1` v2 through its authenticated split endpoint. It returned both existing agent acceptances and `published: true` without a new chain transaction. This checks the live read path; a new web-generated song and album still need an owner browser run.
