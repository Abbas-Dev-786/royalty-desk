# Phase 08 — administrator and listener web app

Depends on: 02–07. Status: not_started. Outcome: the complete studio journey is understandable and operable from the browser.

## Tasks

- **V2-08-01 Navigation:** make the studio and catalogue the primary product. Clearly label or isolate the legacy royalty-administration workspace. Give new visitors a plain explanation of agents, purchases, tips, splits and testnet status.
- **V2-08-02 Administrator:** team creation/identity, policy mode and limits, task board, media/lyrics/versions, split negotiations, review queue, publish/unpublish, emergency pause, sales/earnings/payouts and receipt links. Show exact version and signer before approval.
- **V2-08-03 Agent activity:** display each agent's role, attributed contribution, revision requests, accepted terms, tool/provider run and failure state. Never imply a fixture was live generation.
- **V2-08-04 Listener:** catalogue, album/track pages, playback, credits, price, song/album checkout, tips, purchase status and receipts. Handle wallet rejection, pending payment, refund and access entitlement clearly.
- **V2-08-05 Authorization/accessibility:** authorize every server mutation and private read; protect prompts, keys and drafts. Validate keyboard, mobile, loading/error/empty states and truthful on-chain-versus-local labels.

## Evidence and exit

**WEB-01** full human-review browser flow pauses at protected gates; **WEB-02** autonomous browser flow completes without admin click; **WEB-03** listener buys song/album and tips, sees receipts and correct access; **WEB-04** outsider cannot view drafts or change policy; **WEB-05** rejected wallet, pending chain and missing audio are clear; **WEB-06** mobile/keyboard review. Record browser actor, route, screenshots/video and chain evidence separately. Do not mark a flow passed if a hidden CLI step completes it.
